# Гибридная система синхронизации AI памяти

Автоматическая синхронизация между SQLite (Persistent AI Memory) и Neo4j (граф знаний).

## Компоненты системы

### 1. Инкрементальная синхронизация (`incremental_sync.py`)
- **Назначение:** Обработка только новых/измененных записей
- **Частота:** Ежедневно в 03:15
- **Время выполнения:** 2-10 секунд
- **Ресурсы:** 100-150MB RAM

### 2. Валидация целостности (`validate_integrity.py`)
- **Назначение:** Проверка консистентности данных между системами
- **Частота:** Еженедельно (воскресенье в 02:30)
- **Время выполнения:** 30-60 секунд
- **Автовосстановление:** При критических ошибках запускает полную миграцию

### 3. Управление cron задачами (`setup_cron.sh`)
- **Установка/удаление** автоматической синхронизации
- **Тестирование** компонентов системы
- **Мониторинг** статуса задач

## Механизм работы

### Инкрементальная синхронизация
1. Проверка новых записей в SQLite по `timestamp_created/updated`
2. Создание/обновление узлов в Neo4j
3. Создание семантических связей для новых узлов
4. Сохранение состояния синхронизации

### Валидация целостности
1. Сравнение количества записей SQLite vs Neo4j
2. Проверка целостности связей в графе
3. Поиск orphaned узлов и дубликатов
4. Автоматическое восстановление при критических ошибках

## Расписание выполнения

- **03:15 ежедневно** - Инкрементальная синхронизация
- **02:30 воскресенье** - Валидация целостности
- **01:00 1-го числа** - Ротация логов (удаление старше 30 дней)

## Мониторинг и устранение неполадок

### Проверка логов
```bash
# Последние записи синхронизации
tail -20 logs/sync_daily.log

# Ошибки в системе
grep -i error logs/*.log

# Статистика синхронизаций
grep -c "Синхронизация завершена" logs/sync_daily.log
```

### Ручной запуск
```bash
# Инкрементальная синхронизация
cd /home/dev-avk/projects/persistent-ai-memory
source venv/bin/activate
python incremental_sync.py

# Валидация целостности
python validate_integrity.py

# Полная миграция (при критических ошибках)
python migrate_sqlite_to_neo4j.py
```

### Типичные проблемы

**Проблема:** "Новых записей не обнаружено" при наличии изменений
**Решение:** Проверить `.sync_state.json`, возможно сброс состояния

**Проблема:** "Neo4j недоступен"  
**Решение:** `sudo systemctl status neo4j`, перезапустить при необходимости

**Проблема:** Высокое потребление ресурсов
**Решение:** Система оптимизирована, но при 1000+ записях рассмотреть разделение данных

## Масштабирование

При росте базы данных свыше 500 записей:
- Рассмотреть партиционирование по времени
- Увеличить частоту инкрементальной синхронизации
- Настроить мониторинг производительности Neo4j

## Удаление системы

```bash
# Удаление cron задач
./setup_cron.sh remove

# Удаление файлов состояния (опционально)
rm -f .sync_state.json
rm -rf logs/
```
